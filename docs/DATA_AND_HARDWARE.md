# Data and Hardware Notes

SYNTRA's model initializes randomly. Its weights and tokenizer are not downloaded from a third-party model provider. The local corpus loader enforces a hard 10-million-token ceiling, caps individual text files at 1 MiB and file count at 10,000, and excludes common generated/checkpoint/run directories and likely credential files. These are careful heuristics, not a guarantee that every secret-like file or secret embedded in ordinary source code can be recognized; only train on content permitted for this use.

The default tokenizer uses a corpus-trained byte-pair merge table, saved inside each checkpoint. Its vocabulary size can be configured from 258 to 8,192 IDs. Default model context is 4,096 BPE tokens, with supported values up to 16,384. A longer window uses more memory/compute and does not by itself improve reasoning. Before training and instruction fine-tuning, SYNTRA estimates activation, attention, and optimizer memory and refuses settings above 70% of currently available RAM/VRAM; this conservative estimate reduces OOM risk but is not a guarantee. Instruction JSONL is capped at 100 MiB, individual records at 1 MiB, prompt/completion fields at 512 KiB, 10,000 examples, and 3 million packed tokens.

The setup script creates an isolated Python environment and installs CPU-only PyTorch by default. The launcher selects CUDA or Apple MPS only when available in the installed PyTorch runtime. A Windows PowerShell launch path is included, but hosted Linux CI does not prove every Windows environment is working; run the local install and smoke tests on the target laptop.

The data split estimates next-token loss and is only independent if its validation examples have not appeared in training. Fresh evaluation is a new sample over the requested corpus, not a code-correctness benchmark. Use dedicated, repeatable task benchmarks for software-engineering quality.
